Installation guide

Install and run the Standup Bot

For whoever deploys the app. Slack and Redmine are both hosted services; you run only the bot, on a server Slack can reach over HTTPS.

How it fits together

The bot is one Node.js process. It receives Slack's requests, reads and writes Redmine, and serves the web dashboard. All on one port.

  • Slack → bot. Slash commands, button clicks, the issue search box, and form submits all arrive at /slack/events.
  • Bot → Slack. Opening the form, posting the report, sending reminders.
  • Bot → Redmine. Every read and write uses the Redmine API key of the person using the form. Redmine therefore attributes each comment to that person.
  • Database. A single SQLite file on the bot's server. It holds the Slack-to-Redmine links and the history of submissions. There is no database server to install.

Requirements

WhatNeeded
Node.js22.18 or later. Node runs the TypeScript sources directly, so the server has no build step.
A serverAny Linux, macOS or Windows machine that Slack can reach at a public HTTPS address.
RedmineREST API enabled. Version 5.0 or later is recommended; see step 1.
SlackPermission to create and install an app in your workspace.
Build toolsUsually none. better-sqlite3 ships prebuilt binaries for common platforms. On an unusual platform, npm compiles it and needs Python and a C++ compiler.

1. Prepare Redmine

  1. Enable the REST API. As a Redmine administrator, open Administration → Settings → API. Tick Enable REST web service and save.
  2. Check the version. Redmine 5.0 and later can return the statuses a person may move an issue to under its workflow. The form then offers only those. Older versions return no such list, and the form offers every status instead.
  3. Check permissions. Each person's role needs the Add notes permission on their projects. To change a status from the form, the workflow must allow that transition for their role. The bot never works around Redmine's permissions.

You do not need a shared admin key. Each person's own API key is added to the bot in step 6.

2. Create the Slack app

Pick the public address the bot will have first, for example https://standup.example.com. Slack needs it in the app's settings.

  1. Open api.slack.com/apps and choose Create New App → From a manifest.
  2. Pick your workspace, and paste the manifest below. Replace standup.example.com with your address in all four places.
  3. Create the app, then choose Install to Workspace.
  4. Copy two values for step 4:
    • OAuth & Permissions → Bot User OAuth Token, starting xoxb-.
    • Basic Information → App Credentials → Signing Secret.
  5. Invite the bot to the channel reports go to: type /invite @Standup Bot in that channel.
display_information:
  name: Standup Bot
  description: Daily standup updates, pre-filled from Redmine
features:
  app_home:
    home_tab_enabled: true
    messages_tab_enabled: false
  bot_user:
    display_name: Standup Bot
    always_online: false
  slash_commands:
    - command: /update
      url: https://standup.example.com/slack/events
      description: Submit your daily update
      should_escape: true
    - command: /dashboard
      url: https://standup.example.com/slack/events
      description: Open the standup dashboard
      usage_hint: "[--p @person]"
      should_escape: true
    - command: /link-redmine
      url: https://standup.example.com/slack/events
      description: Link a Slack user to a Redmine account (admins)
      usage_hint: "@user redmine_user_id api_key"
      should_escape: true
oauth_config:
  scopes:
    bot:
      - commands
      - chat:write
      - im:write
      - users:read
settings:
  event_subscriptions:
    request_url: https://standup.example.com/slack/events
    bot_events:
      - app_home_opened
  interactivity:
    is_enabled: true
    request_url: https://standup.example.com/slack/events
    message_menu_options_url: https://standup.example.com/slack/events
  org_deploy_enabled: false
  socket_mode_enabled: false
  token_rotation_enabled: false

Two settings the manifest sets that the app depends on:

  • should_escape: true. Slack then sends @jane as <@U0123ABC|jane>. Without it, /dashboard --p @jane and /link-redmine cannot tell who you mean.
  • message_menu_options_url. This is where Slack asks for search results as someone types in the "Add issue" box. Without it, the box stays empty.

Slack checks the event URL when you save the manifest. It fails until the bot is running at that address. Save anyway, and return to Event Subscriptions to retry after step 5.

3. Install the app

git clone git@github.com:rt83/slack-standup.git /opt/standup-bot
cd /opt/standup-bot
npm ci
npm run build          # builds the dashboard client into dist/dashboard

npm run build builds only the dashboard's browser code. Run it again after every upgrade.

4. Configure

The app reads its settings from conf/app.yaml in the folder it is started from. conf-sample/ is the template, and it is kept in git. conf/ holds your secrets, and git ignores it.

cp -r conf-sample conf
chmod 700 conf && chmod 600 conf/app.yaml    # it holds the Slack secrets

Then edit conf/app.yaml:

slack:
  botToken: xoxb-your-bot-token
  signingSecret: your-signing-secret
  updatesChannel: C0123456789

redmine:
  baseUrl: https://redmine.example.com

server:
  port: 3000
  publicUrl: https://standup.example.com

database:
  path: ./data/app.db

reminder:
  cron: "0 10 * * 1-5"

timeZone: Asia/Ho_Chi_Minh

Quote the cron expression. An unquoted * at the start of a YAML value has a special meaning.

The file is the only source of settings. Environment variables do not override it. Unknown keys are refused, so a misspelt setting stops the app at start. Otherwise it would be silently ignored.

Settings reference

SettingRequiredWhat it does
slack.botTokenYesThe Bot User OAuth Token, xoxb-…. The app checks it with Slack when it starts, and stops if Slack rejects it.
slack.signingSecretYesProves a request came from Slack. Requests with a wrong signature are refused with 401.
slack.updatesChannelNoThe channel ID reports are posted to, not its name. Open the channel's details in Slack; the ID is at the bottom. Empty means reports are not posted.
redmine.baseUrlYesYour Redmine's address, for example https://redmine.example.com.
server.portNoThe port the app listens on. Default 3000.
server.publicUrlNoThe address people's browsers reach the app at. The /dashboard links are built from it. Default http://localhost:<port>, which only works on the server itself.
database.pathNoThe SQLite file. Default ./data/app.db, relative to the working directory. Created on first start, with its tables.
reminder.cronNoWhen to DM people who have not submitted today, as a cron expression in timeZone. "0 10 * * 1-5" is 10:00 on weekdays. Empty means no reminder.
timeZoneNoThe team's time zone, as an IANA name. It decides what "today" means for the reminder and the dashboard. Default UTC.

The app validates every setting when it starts. If one is missing or malformed, it stops and names each one by its path, for example slack.botToken.

5. Run it

cd /opt/standup-bot
npm start

It prints ⚡️ Redmine standup bot running on port 3000. Start it from the folder that contains conf/: that is where it looks for its settings.

HTTPS and the dashboard

Slack only calls HTTPS addresses. Put a reverse proxy with a certificate in front of the app.

The dashboard has no login of its own. Anyone who can reach /dashboard sees every update. Protect it at the proxy. Do not protect /slack/: Slack cannot log in, and it has its own signature check.

An nginx example, with basic auth on everything except Slack's endpoint:

server {
    listen 443 ssl;
    server_name standup.example.com;

    ssl_certificate     /etc/letsencrypt/live/standup.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/standup.example.com/privkey.pem;

    # Slack's requests: no login, the app verifies Slack's signature.
    location /slack/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
    }

    # The dashboard and its API: behind a login.
    location / {
        auth_basic           "Standup dashboard";
        auth_basic_user_file /etc/nginx/standup.htpasswd;
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
    }
}

Create the login file with htpasswd -c /etc/nginx/standup.htpasswd yourname. Your own SSO proxy works the same way.

Run as a service

On Linux with systemd, this restarts the app if it crashes and starts it at boot. WorkingDirectory matters: it is where the app finds conf/ and, by default, data/.

[Unit]
Description=Redmine standup bot
After=network-online.target
Wants=network-online.target

[Service]
User=standup
WorkingDirectory=/opt/standup-bot
ExecStart=/usr/bin/node src/app.ts
Restart=on-failure

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now standup-bot
journalctl -u standup-bot -f      # follow the logs

6. Link the team

The bot needs each person's Redmine account and API key. Each person finds their key in Redmine under My account → API access key → Show. Their Redmine user ID is the number in their profile URL, for example /users/42.

Then run this in Slack, once per person:

/link-redmine @jane 42 0123456789abcdef0123456789abcdef01234567

Anyone in the workspace can run /link-redmine. There is no admin check yet. Whoever runs it can make Redmine attribute writes to someone else's account. Restrict who may run it before using the bot outside a trusted team; the place to add the check is marked in src/slack/linkRedmineCommand.ts.

The API keys are stored in the database as plain text. Keep the database file private.

Running the command again for the same person replaces their link.

7. Check it works

  1. In Event Subscriptions on api.slack.com, the request URL shows Verified.
  2. A linked person runs /update. The form opens with their open Redmine issues.
  3. They type a number in "Add issue". Matching issues appear.
  4. They submit. Each issue gets a comment in Redmine, and the report appears in the updates channel.
  5. /dashboard replies with a button. It opens the dashboard, which shows the submission.

Upgrades and backups

Upgrade

cd /opt/standup-bot
git pull
npm ci
npm run build
sudo systemctl restart standup-bot

The database schema is created with CREATE TABLE IF NOT EXISTS. An upgrade keeps your existing data.

Back up

Everything worth keeping is in two places: conf/app.yaml and the database file. The database runs in SQLite's WAL mode, so while the app runs, recent writes may sit in app.db-wal beside it. Copying only app.db then misses them. Take a consistent copy with SQLite's own backup command instead:

sqlite3 /opt/standup-bot/data/app.db ".backup '/backups/standup-$(date +%F).db'"

Local development

For working on the code, not for production.

cp -r conf-sample conf     # then fill in conf/app.yaml
npm install
npm run dev                # the app, restarting on change
npm run dev:client         # the dashboard with hot reload: http://localhost:5173/dashboard/
npm test                   # every test, server and client
npm run typecheck          # tsc for the server, vue-tsc for the client

dev:client sends /api requests to the app on the port in conf/app.yaml, so run both. Slack still needs to reach the app over HTTPS to send it commands.

Troubleshooting

What you seeCause and fix
No configuration at …/conf/app.yamlThe app was started from another folder, or conf/ was never created. Start it from the install folder, or set WorkingDirectory in the service.
Invalid configuration … listing settingsThose settings are missing, malformed, or not a setting the app knows. Fix them in conf/app.yaml. An unknown key is usually a typo, or a key at the wrong indentation.
The app exits at start with invalid_authSlack rejected slack.botToken. Copy it again from OAuth & Permissions. Reinstalling the app issues a new one.
Logs show Signature mismatch, and Slack says the app did not respondslack.signingSecret is wrong, or the proxy changes the request body. Pass /slack/ through untouched.
"Your Slack account isn't linked to Redmine yet"Run /link-redmine for that person.
The "Add issue" box never shows resultsThe options URL is missing. Set Interactivity → Select Menus → Options Load URL to https://…/slack/events.
The status dropdown offers every statusRedmine returned no workflow list. It needs Redmine 5.0 or later, and the person needs permission to edit the issue.
A submission shows "redmine sync failed" on the dashboardRedmine refused that write. The reason is in the logs and in submission_items.redmine_error. The usual causes are a revoked API key, a missing Add notes permission, or a status change the workflow does not allow.
Reports do not appear in the channelslack.updatesChannel is empty or is a name rather than an ID, or the bot was never invited to the channel.
/dashboard --p @jane replies with the usage textThe command's Escape channels, users, and links setting is off. Turn it on, as should_escape: true in the manifest does.
The dashboard says "Dashboard client is not built"Run npm run build in the install folder.
The reminder arrives at the wrong hour, or "today" is off by a daytimeZone is not the team's time zone. Set it to the right IANA name.
npm ci fails compiling better-sqlite3No prebuilt binary exists for this platform and Node version. Use a supported Node LTS, or install Python and a C++ compiler so npm can build it.
